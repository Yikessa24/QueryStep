## 实现与计划的核对

学生 Cookie 恢复会话后，服务按递增事件序号读取已判分历史，筛出未练候选。EpiKT 为候选预测答对概率，规则使用同一课程约束。推荐写入前再次检查历史版本，判分仅由提交端点执行。历史记录不混入聊天和模型预测。用户界面显示基础、巩固、进阶以及规则降级来源；模型的 episode、门控和分支从未作为学生的掌握度或错因展示。

模型适配将 KC 放入 `q_data`、二值作答放入 `target`、题号放入 `pid_data`。对同题各 KC 复用同一确认历史，每个目标在独立行的末位评分。用合法占位标签，读取严格因果的末位预测。已验证翻转占位标签和追加未来作答不改变目标分数，200 个位置的在线窗口保留完整作答事件。题目级 KC 均值和 EpiKT 内部分支融合是不同计算；校准沿用 pyKT `late_mean` 四位小数。词表可包含静态留出题目元数据，线上另检查训练折是否见过该题。留出作答没有用于训练和拟合校准。

原计划的主链路和公开可解释性边界已落实。完整版规划中的独立评分进程、CPU／MPS 运行正式 ALiBi、数据库行级策略、跨设备账户和压测尚未交付。当前部署建议是一进程内有界推理，GPU API 可通过 SSH 转发与本机 UI 联调。

下载包未提供 `Study`、`Course`、`Enrol` 的原始练习行。演示题库的补充表为合成数据，保持题目所问的 SQL 操作和官方正确选项，正式离线评估仍使用原历史记录。演示版题目的实际难度和学习收益需要用演示学生数据验证。聚合、集合运算和子查询分别使用对应的审核提示与引用。 [聚合](https://www.postgresql.org/docs/18/tutorial-agg.html) · [集合运算](https://www.postgresql.org/docs/18/queries-union.html) · [子查询](https://www.postgresql.org/docs/18/functions-subquery.html)

题目窗口评估逐一核对行号、位置、题目、KC 和标签。三种基线均只用训练折拟合或统计，在同一作答前缀计算概率，再对多 KC 取均值。准入在题目和 KC 均有训练支持、已有至少三次历史作答的目标上比较最强基线，同时保留标准窗口整体结果和短历史分层。报告包含 AUC、ACC、Brier、NLL、ECE、可靠性分箱和按学习者重采样的配对 Brier 差异区间。BKT 使用四参数无遗忘模型。 [BKT 原论文](https://doi.org/10.1007/BF01099821)

当前 CPU 冒烟的 2,173 个留出目标都能对齐。进入共同准入范围的 1,957 题上，校准 EpiKT Brier 为 0.1462，最强基线题目先验为 0.1338，差异的 95% 配对区间为 [0.0069, 0.0184]，该产物未通过准入。这些数字只用于验证评估脚本和门槛。

## 本轮改动与测试

- **凭据与错误边界。** OpenAI 兼容传输独立封装，拒绝携带内嵌凭据的 URL，默认拒绝远程或带密钥的明文 HTTP，关闭自动代理与跳转。配置错误保持基础练习可用。日志只记录失败类型和 HTTP 状态，不写授权头、学生文本或响应原文。
- **Agent 与课程资料。** 将课程资料与模型传输分开，纠正各主题的引用，限制同一进程最多四轮并发辅导、单轮三次模型调用和两次工具调用。输出校验含阶段、引用、答案泄露及允许的 JSON 格式。校验覆盖部分明显泄露形式，生产使用仍需样本审阅。
- **评估和复现。** 增加真实留出历史的策略回放，可复用在线选择逻辑并区分实际作答与反事实替代题。新训练产物记录整个随附 pyKT Python 源码指纹，同时保持旧冒烟产物可读。
- **可用性与运行成本。** PostgreSQL 连接池取用连接时先检查连接状态。默认 SQLite 新建文件权限为仅当前账户读写。数据处理依赖延迟导入，默认 API 启动不加载 pandas。界面补充答错状态、练习方向和降级说明。
- **演示配置。** 本机 `.env` 的 Gemini 等待上限设为用户成功探针所用的 30 秒。映射到研究数据的题默认使用审核提示。启用这类题目的外部辅导时，需另核对能否转发学生自由文本。

## 应用价值和简历定位

实际栈为 Python、FastAPI、SQLAlchemy、SQLite／PostgreSQL、PyTorch、随附 pyKT、React／TypeScript、HTTPX、Pydantic、显式 Agent 工作流和本地课程检索。Docker Compose 是已准备的部署路径。LangGraph、LangChain、向量数据库、重排和 Redis 均未参与当前主链路。

面试中最有区分度的是三条可证明的设计。首先是把知识追踪概率接入约束选题，并能在同一输入上回放规则对照。其次是为多 KC 保留原题和事件边界，验证因果隔离及离在线一致性。最后是把 LLM 限制在只读辅导工具和可校验动作内，将事务账本及选题留给服务端。现有工程足以展示受控 SQL 教学试点的设计和实现。可以展示真实 Gemini 探针和冒烟对照链路，正式选题表现和教学收益要以各自验收结果支持。
