# QueryStep 七天学习与 AI 接续指南

这份指南供学习者和带教 AI 在不同设备上接续。目标是在一周内掌握 QueryStep 的用户流程、后端实现和 Agent 工程，能独立演示项目、定位源码、解释取舍与实测结果，并把项目用于 AI 应用和 Agent 开发实习面试。学习者已理解自己设计的 EpiKT 模型，本周重点学习它如何接入选题，以及项目中其余的后端和 Agent 模块。

时间按 **7 天、每天 3 小时，共 21 小时**安排，另留约 **4 小时机动**。每天建议用 20 分钟复现操作、110 分钟带读后端代码、35 分钟验证、15 分钟复述。优先级是 **Agent → 后端 → 前端**。用 [本地启动与体验手册](QueryStep%20本地启动与体验手册.md) 的按钮、答案和提问走页面，按本指南找每个操作对应的代码与结果。

## 给接续教学的 AI

1. **从操作开始，从后端接收处细讲。** 每次说清按钮和对应接口，然后沿实际调用链看后端接收到的字段、查到的数据、分支选择、模型和工具的输入输出、持久化、页面结果及异常处理。前端事件绑定、样式和 HTTP 封装点到为止。
2. **先带读，再操作，最后追问。** 用三到十行真实代码讲一个小段，解释变量从哪里来、这一行做什么、返回后谁继续用。当学习者刚接触一段代码时，先用实际数据替换变量解释一遍，等读懂后再问一个具体问题。答不上时一起回到相应代码行，换个更短的例子，再让学习者用自己的话复述。
3. **把责任说到具体模块。** 遇到纯业务操作，讲清确定性规则、数据读写和校验。遇到模型路径，明确是 EpiKT 评分、Gemini 响应、LangGraph 编排、MCP 工具调用还是 RAG 检索。对比两条教练路径时，分别核对实际入口和工具范围。
4. **跟着证据走。** 能打开源码时按函数名定位。让学习者用 Safari 网络面板、页面轨迹、报告或测试核对结论。代码示例标明真实片段或简化示意。每课结束更新「接续记录」，按已操作、已读懂、已独立复述区分进度。

**换设备后可直接发给 AI 的开场消息**

> 请按这份 QueryStep 七天学习与 AI 接续指南带我学。我的目标是一周内弄懂项目并准备 AI 应用／Agent 开发实习面试。我熟悉 EpiKT 模型，Agent 和后端需要从实际代码学起。从「接续记录」的下一步开始。网页怎么触发请求简单带过，从后端收到数据开始逐行讲。请先用我实际看到的输入输出带我读懂一小段，再问一个问题。源码和本机环境可用时先核对。设备目前只有这份文档时，先用文中的已验证响应讲清链路。

## 换设备后怎么开始

1. 在新设备打开 QueryStep 仓库根目录。优先读取本指南、[体验手册](QueryStep%20本地启动与体验手册.md)、[部署操作指南](../deploy/OPERATIONS.md)。本文源码链接相对仓库目录，行号用于快速跳转，代码变动时以函数名定位。旧设备的浏览器 Cookie 和本地学习库各自保存在原设备，演示路线可以用新会话重走。
2. 先确认代码、Python 环境、前端依赖和可用的题库。真实 Gemini 需要当地可用的模型配置。正式 EpiKT 建议从原设备单独取回完整 run 目录和获准展示的匹配题库。混合 RAG 需要课程索引和匹配的本地嵌入模型。按体验手册第 5 节和部署操作指南恢复，模型密钥只在本机配置。
3. 在项目根目录按体验手册 §1 启动。原 Mac 的命令使用 `artifacts/diagnostics-venv/bin/python`，新设备应选实际存在、已安装项目依赖的 Python 环境。默认网页是 `http://127.0.0.1:5173/`，默认 API 健康检查是 `http://127.0.0.1:8000/healthz`。先确认需体验的模块是否就绪。Gemini 能否真实调用工具，以探针或一次实际对话的结果为准。
4. 环境还在准备时，可以先读源码并用上面的已验证响应复盘 Day 1。有测试依赖时，可用模型替身验证工具协议和降级，例如从仓库根目录执行 `python -m pytest -q tests/test_tutor.py -k two_turns_adapt_and_use_returned_tools`。进度里分别标记「历史实测」「本机替身复验」「本机真实复验」，便于以后对照。真实调用统一用手册中的合成教学问题和独立会话。

## Day 1 · Gemini 对话与工具调用

**对应手册 §1、§2.6、§6。** 在当前聚合错题点「问问助教」。连发两轮，第一轮请使用 `retrieve_course_notes`，第二轮请使用 `get_worked_example`。Safari 的「网络」面板筛选 `tutor`，用「预览」读项目 API 响应。用 Enter 和发送按钮体验提交，核对 Shift + Enter 换行、发送后清空、思考中、请求失败恢复草稿。

按以下顺序带读后端：

1. [API 入口](../api/main.py#L269) 处理 `POST /api/practice/{decision_id}/tutor`，接收 `message` 和当前学习者信息。进入 [Practice.tutor_turn](../api/practice.py#L203)，看题目从哪来、已有对话怎么读、相关笔记怎么找。
2. [TutorAgent._respond](../tutor/agent.py#L88) 构造题目主题等上下文，组装系统提示、近期对话和当前消息。找到 `prior[-2:]`、最后一条用户消息和 `TOOLS`。用 [ChatModel.reply](../tutor/provider.py#L64) 看 JSON 请求体怎样加入工具定义并发往 `chat/completions`。
3. 模型返回 `tool_calls` 时，由后端校验工具名、调用 ID 和参数。沿 [工具分发](../tutor/agent.py#L60) 进入 [课程例题字典](../course_content/lessons.py#L21)，对照 `example-aggregate`。这里是普通助教的本地函数调用。
4. 看 [工具结果回传](../tutor/agent.py#L141) 怎样记录 `trace`，并用 `role: "tool"` 与 `tool_call_id` 把结果送回 Gemini。跟到结构化回复和引用校验、备用提示、`TutorTurn` 入库和页面渲染。

**验证与追问。** 学会用 `trace` 确认执行，用 `citations` 确认最终引用，用 `source` 和 `fallback_reason` 判断回复状态。先让学习者能画出「浏览器一次请求，后端两次调用模型」。再问他 `tools`、`tool_calls` 与 `role: "tool"` 分别在谁发给谁的消息中出现。最后看手册 §6 的探针怎样区分模型联通、函数调用和结构化输出。

2. **75 分钟工程复验。** 理解独立数据库、合成会话、Playwright 模拟 API 与真实模型验收各能验证什么。跟着手册读测试命令和课程索引指纹检查，运行一个小范围模拟或本地测试。读标签审计的 100 个案例、60 开发／40 测试划分和四场景三种子的口径，再从已有四组报告追直接回答、课程 RAG、动态 Agent 和无学习上下文 Agent 的输入、正确判定、误指责、有效反例、延迟与费用缺失。人工验收学习教师独立核对、参与者同意、记录帮助性和观察迁移的方法。完整四组重测和真人试用沿用已有暂缓安排。
3. **60 分钟面试。** 练 90 秒介绍、5 分钟演示和 20 分钟追问。演示依次展示 EpiKT 选题、SQL 教练反例和 RAG 课程证据。用剩余时间回查答不上来的函数或指标。结合 [工程审计报告](工程审计与交付报告.md) 分清预测表现、选题回放、软件可靠性和学习收益各需要什么证据。

**最终验收。** 从体验手册随机抽三个操作，至少覆盖一个普通助教链路、一个动态教练或检索链路和一个纯后端操作。每个在两分钟内讲清「后端入参 → 状态读取 → 决策或工具 → 结果校验 → 持久化 → 页面和异常」。再选一个已复现的行为，展示对应源码和可重复的验证方法。
